# Капри и Ди

Личный учебный ассистент Alex. **Капри — она**, общается в Telegram и работает через
OpenRouter. **Ди — он**, читает LMS/Time, готовит домашки по запросу и проходит
разрешённые учебные тесты через Codex CLI и свой браузер.

```text
Alex → Telegram → Капри (OpenRouter) → SQLite-очередь → Ди (Codex CLI)
                     ↑                                  ↓
                 дайджест ← структурированный результат + файлы
```

Это первый рабочий прототип приложения, а не подтверждение установки на сервер.
Сетевые входы и реальные учебные действия требуют отдельной проверки. В репозитории
нет токенов или данных из учебных сервисов. LM Studio для прямого OpenRouter не нужен.

## Что реализовано

- Переписка с единственным владельцем в личном Telegram-чате; остальные отправители игнорируются.
- Капри вызывает только фиксированные инструменты: поручение Ди, статус,
  поиск прошлых результатов, заметки памяти и личный список дел с напоминаниями.
  Она не генерирует исполняемые shell-команды. Английский промпт персоны:
  `capri_di/prompts/capri.md`. Язык общения определяется сообщением пользователя;
  дайджесты пишутся в свободной форме, без фиксированного шаблона.
  Капри не обращается по настоящему имени, а редкие прозвища остаются частью
  естественной речи. Обычные сообщения не содержат технических статусов и job ID.
- В стандартный дайджест входят только актуальные несданные учебные задания.
  Архивные курсы, явно неактуальные задачи, нормативные ознакомления и сданное/
  «На проверке» исключаются до форматирования. Настоящие просрочки текущих курсов
  сохраняются. Условия задаются в инструкциях Ди и проверяются кодом.
- Time: содержательные новые учебные объявления, договорённости и сроки;
  после успешного сбора передаётся отметка времени для следующей выборки.
- Ди получает конкретный job через `codex exec`, возвращает проверяемый JSON и файлы.
  Инструкции: `capri_di/prompts/di.md`. Подготовка домашки отделена от `/submit ID`.
  Запуск использует `--approve-for-me`: действия проходят автоматическую проверку,
  ограничения `workspace-write` сохраняются. Отказы проверки не обходятся.
- Durable inbox, очередь, результаты, память, список дел и outbox в SQLite.
- Один Ди одновременно: браузерный профиль не делится между параллельными заданиями.
- После сбоя выполнявшаяся задача получает `unknown`, не повторяется автоматически.
  Отправки Telegram резервируются до вызова API; неизвестные отправки не повторяются.
- Плановый сбор LMS ежедневно в 18:00 МСК, Time в 08:00, 12:00, 16:00, 20:00;
  с 00:00 до 08:00 плановые сборы и отправки Time приостановлены. Запоздавший
  отчёт дождётся утра. Ручной `/time` доступен и ночью. Тесты в 10:00 МСК.
  Время отправки дайджеста — после завершения сбора. Флаги расписаний выключены до настройки.
- Отдельные системные пользователи: Капри не читает auth/browser Ди; Ди не читает env Капри.

## Установка на Ubuntu 24.04

Исходный код публичный, в личном GitHub AlexProts. Конфигурация, переписка,
результаты и доступ Codex остаются только на доверенном личном сервере.
Не копируйте в Git старые архивы конфигурации, `.env`, `auth.json` и browser profile.
Не запускайте подписочную сессию Codex в публичном CI или на непроверенных PR.

```bash
git clone https://github.com/AlexProts/capri-di.git
cd capri-di
sudo bash deploy/install.sh
sudo nano /etc/capri-di/capri.env
```

Введите вручную Telegram-токен, username бота без @, ID своего private чата, OpenRouter-ключ и ID модели
с поддержкой tools. Env — синтаксис systemd `NAME=value`, без `export`; не показывайте
его содержимое в чатах. Установщик не запускает сервисы и не перезаписывает конфиги.
Если системный Node.js старее 20, установщик загрузит официальный Node.js 22
в `/opt/capri-di/node`, проверив SHA-256. Системный Node.js не заменяется.

### Вход Ди через подписку ChatGPT

```bash
sudo -u di env HOME=/var/lib/capri-di/di CODEX_HOME=/var/lib/capri-di/di/.codex \
  /opt/capri-di/node_modules/.bin/codex login --device-auth
sudo -u di env HOME=/var/lib/capri-di/di CODEX_HOME=/var/lib/capri-di/di/.codex \
  /opt/capri-di/node_modules/.bin/codex login status
```

Код входа вводите сами на официальном сайте. Параметр `forced_login_method="chatgpt"`
исключает неявный переход на API-ключ. Подписка даёт свои лимиты Codex; доступность
модели/квота проверяются реальным запуском, а не только статусом входа. OpenRouter
оплачивается отдельно. Кэш auth Ди остаётся на сервере и никогда не публикуется.

### Отдельный браузер Ди

Playwright MCP запускается Codex по stdio с постоянным профилем. Настройки:
`/etc/capri-di/browser.json` и `/var/lib/capri-di/di/.codex/config.toml`.
Входы из ChatGPT Work сюда не переносятся автоматически.

Первый вход в LMS/Time выполните сами в графическом браузере сервера. Нужен
SSH-туннель к временному рабочему столу/VNC, доступному только на loopback.
Отдельный скрипт установит минимальный рабочий стол, приостановит Ди на время
входа и восстановит его прежний статус после закрытия браузера:

```bash
sudo bash /opt/capri-di/deploy/login-desktop.sh lms
# После закрытия браузера аналогично: ... login-desktop.sh time
```

Скрипт покажет команду SSH-туннеля; на Mac откройте `vnc://127.0.0.1:5901`.
Не публикуйте VNC/CDP в интернет. На этом этапе нужен ручной вход; нельзя обещать сбор,
пока его не проверили. Ошибка старого облачного браузера Work не доказывает доступность
Time на сервере. Не обходите отказы безопасности и права доступа.

### Первый запуск и переход со старой рассылки

```bash
sudo systemctl enable --now di capri
sudo systemctl status di capri
```

В Telegram: `/status`, затем `/digest`. Это запустит один **read-only** сбор LMS.
Проверьте полученный дайджест и подтверждение Telegram на сервере. Затем проверьте
Time вручную, включив `TIME_ENABLED=true`, и отправив `/time`.

После успешного теста **приостановите старые облачные рассылки** в ChatGPT,
если они есть. У этого приложения отдельная база доставки: оно не дедуплицирует
отправки активного ChatGPT Work. Ничего в Work установка сама не меняет.

Теперь выставьте `SCHEDULES_ENABLED=true` в env и перезапустите `capri`.
`PROACTIVE_TESTS_ENABLED=true` включает ежедневные тесты в 10:00; включать после
проверки входа и доступных тестов. Ди не перепроходит завершённые попытки.
Смена расписаний в естественной речи пока не реализована: настройте env и restart.

Команды: `/help`, `/digest`, `/time`, `/tests`, `/do текст`, `/submit JOB_ID`,
`/files JOB_ID`, `/status`, `/style пожелание`, `/memory [КЛЮЧ]`, `/forget КЛЮЧ`,
`/todo [текст]`, `/done ID`, `/cancel ID`, `/continue JOB_ID уточнение`. Файлы домашек сохраняются в
`/var/lib/capri-di/shared/artifacts/JOB_ID/`; `/files JOB_ID` отправляет их в Telegram
один раз (до 20 MiB на файл).

## Память и контекст

Всё хранится на сервере в `/var/lib/capri-di/shared/assistant.db`, без внешней
базы/векторного сервиса. Изменения схемы и перенос прежнего предпочтения происходят
автоматически при запуске. Секреты и браузерная авторизация в память не копируются.

- В обычный ответ входят последние 40 сообщений (включая команды и ответы),
  с ограничением истории в 16 000 символов, и краткое резюме старой переписки.
  После накопления более 60 сообщений Капри сжимает старый фрагмент отдельным
  запросом к той же настроенной модели OpenRouter. Итог — до 6000 символов.
  При ошибке провайдера исходные сообщения сохраняются для следующей попытки.
  Это дополнительный расход токенов время от времени, не постоянный фоновый агент.
- Пожелания и учебные факты хранятся отдельными заметками: до 24 ключей,
  до 2000 символов на заметку и до 8000 суммарно. `/style` заменяет только заметку
  `style`; `/memory` показывает список, `/memory КЛЮЧ` — полный текст,
  `/forget КЛЮЧ` — удаляет заметку. Это не удаление архивов inbox/outbox/переписки.
- Последние три действительно доставленных отчёта передаются дословно, чтобы
  продолжать разговор про «вторую домашку». Также доступны последние поручения,
  открытые дела и поиск по словам в последних 100 заданиях Ди. По ID можно
  прочитать конкретный более старый результат. Большие результаты возвращаются
  частично с явной отметкой; даты и ссылки не обрезаются внутри выбранной записи.
- Ди получает неизменяемый снимок недавнего разговора, прошлого дайджеста,
  резюме и найденных результатов при постановке поручения. Это справка к текущей
  задаче, не разрешение выполнять старые поручения заново. Сессия Codex по-прежнему
  новая на каждый job. Старое наблюдение проверяется в LMS/Time при необходимости.
- Это память серверного приложения. Obsidian, `init-context`/`wrap` и старые чаты
  ChatGPT Work не подключаются автоматически. Резюме может потерять детали;
  память не гарантирует дословного воспроизведения всей истории.

Внутренние функции `delegate`, `remember`, `recall`, `todo` — не команды Telegram.
Например, `/delegate` и `/remember` не существуют. Неизвестная команда теперь
отклоняется до обращения к модели; список поддерживаемых команд всегда в `/help`.

## Дела и напоминания

Можно писать обычными сообщениями: «добавь дело разобрать NLP», «напомни завтра
в 10:00 про домашку», «напоминай про проект каждые 24 часа, начиная завтра в 18:00»,
«перенеси напоминание на пятницу, 20:00», «закрой дело про NLP». Капри должна
уточнить неоднозначность, сохранить изменение инструментом и подтвердить конкретную
дату/время. По умолчанию — Москва; другой часовой пояс нужно указать явно.

`/todo` показывает открытые дела, `/todo текст` добавляет дело **без напоминания**.
`/done ID` завершает, `/cancel ID` отменяет дело и останавливает его уведомления.
Срок дела и время уведомления независимы: один только дедлайн ничего не отправляет.
Создание дела не запускает Ди; выполнить его нужно попросить отдельно.

Напоминания проверяются в обычном цикле бота, не расходуя токены, в том числе
при выключенном расписании учебных сборов. Для них не нужны MCP/cron/другая LLM.
Капри должна оставаться запущенной; длинный запрос к провайдеру может задержать
уведомление. После простоя приходит максимум одно догоняющее уведомление на дело,
а не пачка за каждый пропущенный период. Изменение/закрытие отменяет старые ещё
не отправленные уведомления. Уже начатую или неизвестную отправку отозвать нельзя;
неизвестные доставки автоматически не повторяются. Дела переживают перезапуск.

Капри не создаёт дела из чужих сообщений Time/LMS автоматически и не меняет
учебные расписания через заметки памяти. Для действий требуется запрос владельца.

## Проверка и ограничения

### Общение обычными сообщениями

Основной интерфейс — текст, команды остаются необязательными сокращениями.
«Отправь ещё раз Ди задачу на рек сис» выбирает продолжение, «пришли файлы» —
получение файлов в Telegram, «прикрепи готовую домашку» — сдачу только конкретного
готового решения по явному запросу. Подготовка/продолжение не означает сдачу.

Каждый обычный запрос обрабатывается через обязательный структурированный выбор
следующего шага (`route_request`): инструмент, содержательный ответ либо уточнение.
Провайдер получает принудительный выбор этой функции, а не `tool_choice=auto`.
Капри не может выдать произвольный текст вместо результата маршрутизации.
Она получает каталог инструментов, последние поручения, исходный запрос, память
и найденные учебные записи. Поиск понимает «рек сис», «рек сисом», `recsys` и
официальное название курса. Инструменты исполняет код с прежними проверками.

При отсутствии ссылки Капри сначала ищет её в сохранённых данных. Если работа
одна, она подставляется автоматически; если подходят несколько, вопрос задаётся
по их названиям: «ДЗ 4 про графовые сети или ДЗ 5 — соревнование?». Незавершённый
запрос сохраняется между уточнениями: ответ «четвёртую» продолжает тот же процесс.
Внутренняя ошибка возвращается модели для следующего шага, а не пользователю как
инструкция использовать `recall` или вручную вводить `/continue`.

Для выбора шагов используется недорогая вспомогательная модель
`google/gemini-2.5-flash-lite` с тем же ключом OpenRouter. Она не работает в фоне; основная
модель и персона сохраняются для переписки, дайджестов и резюме памяти.
Переопределение — `OPENROUTER_ROUTING_MODEL`; пустое значение использует основную.
При недоступности вспомогательного провайдера маршрутизация на 15 минут переходит
к основной модели; повторных постановок задач при этом не происходит.
Решение содержит тип процесса: продолжение не должно превращаться в новую домашку.
Если модель одновременно выбирает исполняемый инструмент и пишет вопрос, решение
отклоняется до любых действий и запрашивается заново. Лимит — 6 шагов на сообщение. Для
отдельной проверки на реальной модели (расходует немного API-токенов):

```bash
sudo bash deploy/check-routing.sh
```

Проверка использует временную БД и тестовые учебные записи, не отправляет Telegram,
не запускает Ди, не открывает LMS и не сдаёт работы. Проверяет выбор между двумя
домашками, постановку продолжения после уточнения и напоминание обычным текстом.

### Уточнения и продолжение домашек

Для постановки homework нужна одна точная ссылка LMS: Капри берёт её из запроса,
дайджеста/поиска результатов или уточняет, какая работа нужна. Поручение вида
«ДЗ 4 или 5» не ставится в очередь. Ди получает ссылку, полное поручение, исходное
сообщение владельца и ограничения; перед решением сверяет тему и условие в LMS.

Если Ди остановился, «разрешаю установить библиотеки, пусть доделает» передаётся
через отдельный инструмент continue_homework, а не через чтение статуса. Создаётся
новый связанный job; прежний blocked/unknown не переписывается. Если родитель ещё
работает, продолжение ждёт его результата. Капри подтверждает постановку в очередь
кодом приложения, без возможности объявить её уже запущенной словами модели.

Ручной вариант: `/continue JOB_ID --deps Установить библиотеки, проверить решение,
не прикреплять`. Без `--deps` — обычное уточнение. Для старой задачи без точной
ссылки нужно добавить её в уточнение. Продолжение получает прежние обычные файлы
в `previous/`, прошлый результат, исходное поручение и новое уточнение. Окружения,
скрытые каталоги, ссылки, старые AGENTS/конфиги авторизации не копируются. Лимит
снимка — 500 файлов/100 MiB; пропуски отмечаются явно. Итоговые файлы сохраняются
в `artifacts/` нового job; частичные результаты доступны через `/files` и при blocked.

Разрешение `install_dependencies` хранится в конкретном поручении, не в памяти
стиля. Оно допускает установку необходимых библиотек из официальных источников
только в `.venv` рабочей папки, без sudo, системного pip и изменения сервера.
Разрешение сохраняется при продолжении той же домашки; при смене ссылки требуется
новое. Сдача по-прежнему только по явному запросу владельца — через `/submit`
или обычное сообщение с однозначно выбранной готовой работой. Тесты/сдачи этим
механизмом не перезапускаются; неизвестные внешние действия автоматически не повторяются.

Для обновления установленного кода без смены env и входов:

```bash
git pull --ff-only
sudo bash deploy/update-code.sh
```

Чтобы этим же обновлением применить согласованное расписание дайджестов:

```bash
sudo bash deploy/update-code.sh --study-schedule
```

Флаг включает плановые сборы и Time, устанавливает LMS на 18:00, интервал Time
4 часа и ночной перерыв 00:00–08:00 МСК. Настройки записываются отдельно в
`/etc/capri-di/digests.env`, подключаемый через systemd drop-in; они имеют приоритет
над прежними часами в `capri.env`. Ключи/токены и флаг проактивных тестов не меняются.
Впоследствии часы меняются в `digests.env` с перезапуском `capri`. В указанный час
начинается сбор; отчёт отправляется после завершения Ди, а не гарантированно в 18:00.

Если у Ди есть задания в очереди или в работе, обновление откажется их прерывать;
дождитесь результата и повторите команду. Уже доставленные отчёты не отправляются заново.

Если Ди сообщает, что инструмент требует одобрения, а текущая политика запрещает
его запросить, обновите старую установку:

```bash
sudo bash deploy/repair-browser.sh
```

Скрипт включает штатную автоматическую проверку Codex и источник Time,
сохраняет ограничения рабочей папки, env и браузерную сессию. Старые задачи
не переигрываются; доступ к источникам подтвердите новыми `/digest` и `/time`.
Конкретный отказ автоматической проверки остаётся блокером, а не разрешением обхода.

Если обе службы падают с `attempt to write a readonly database`, выполните:

```bash
sudo bash deploy/repair-storage.sh
```

Скрипт останавливает обе службы, восстанавливает групповые права только для общей
БД и её журналов, проверяет запись от `capri` и `di`, затем запускает службы.
Данные, env и авторизация не удаляются.

```bash
python3 -m unittest discover -s tests -v
```

Тесты выполняются без сети/ключей: конкуренция claims, дедупликация, перезапуски,
доступ владельца, границы файлов, вызов CLI через отдельный fake-процесс.
Они не доказывают доступ к LMS/Time, правильность ответа модели, сдачу или доставку.

Входящие вложения, голосовые и отмена выполняющейся задачи
пока не поддерживаются. Квоты/ошибки CLI дают unknown, а не автоматический retry.
SQLite рассчитан на один сервер с локальным диском. Резервируйте БД штатным SQLite
backup, отдельно и с ограниченными правами храните auth/browser и env. Логи приложения
не содержат HTTP URL с токенами; Codex ведёт собственную приватную историю под `di`.
